# AI Quant Development Router

## 定位

把“新量化策略/模型开发”路由成可验证的增量闭环。自动触发本 skill，但不自动决定模型是否有效、不替代专业实现 skill，也不要求每个项目一开始就建设完整平台。

核心原则：

> 每轮只推进一个可运行、可检查、可解释的最小闭环；迭代速度服从数据语义、金融逻辑和风险门禁。

## 触发边界

### 强触发

用户明确要求新建、开发、搭建、实现或系统化以下任一对象时触发：

- 量化策略、交易策略、资产配置模型、组合模型、风控模型；
- 因子、标签、信号、评分、回测流程或策略研究项目；
- 把研究想法做成可复跑项目、服务、API、报告或前端；
- 为新模型增加回测评审页、交互页面、运行状态、监控或工作台。

有无前端都触发；前端只是后续可选分支。

### 条件触发

“优化/完善/升级某模型或页面”如果可能同时影响模型逻辑、数据口径、API、输出契约和前端交互，先按跨层变更处理；若只是单文件样式、文案或明确的局部 bug，路由到相应专门 skill，不启动完整流程。

### 不触发

- 解释概念、比较方法或讨论策略想法；
- 一次性取数、单次计算、快速画图或轻量验证；
- 已有项目的孤立小修复、文案/颜色/列顺序调整；
- 只查询 API 用法，或只要求阅读当前项目进度。

不触发不等于不验证：按 `quant-research-coding`、`systematic-debugging`、`quant-project-review` 或其他专门 skill 处理。

## 路由职责

本 skill 只负责四个判断：

1. 当前是新项目、研究原型、候选定型、正式跟踪还是跨层增量开发；
2. 本轮最小可验证闭环是什么，以及明确不做什么；
3. 需要加载哪些专业 skill；
4. 本轮是否达到人工确认、继续、回退、升级或暂停的条件。

不要在本 skill 中重复实现量化计算、API、前端组件或测试细节。专业规则由被路由的 skill 负责。

## 启动检查

自动触发后，先用简短文字复述并确认以下信息；缺失时只追问会改变主路径的问题：

- 量化对象和核心假设；
- 主要消费方、运行频率和输出用途；
- 新项目还是已有项目，已有项目的当前阶段；
- 数据源、关键字段、单位、时间口径和 PIT 可见性；
- 当前轮的最小闭环与明确非目标；
- 是否需要报告、前端、API、监控、发布或人工操作。

不要因为用户提到“快速”就跳过数据口径、输出契约、失败条件或风险约束。

## 专业技能路由

| 当前需要 | 路由 skill | 选择要点 |
|---|---|---|
| 一次性探索、轻量回测、可复跑研究 | `quant-research-coding` | 先做最小研究入口和样本验证，不默认项目化 |
| 可复用项目、固定契约、定期运行、投资流程消费 | `quant-develop` | 补项目结构、preflight、日志、契约、运行证据 |
| 页面是报告、回测评审或候选定型说明 | `frontend-page-router` → `frontend-report-page` | 先 preview，研究期默认静态 HTML |
| 页面是定型模型跟踪、日常操作、监控或发布门禁 | `frontend-page-router` → `frontend-ops-platform` | 先确认工作台/只读监控，按状态机实现 |
| 发现失败、异常、竞态、口径冲突或性能问题 | `systematic-debugging` | 先复现和根因调查，再提出单一修复 |
| 高风险新行为或回归防护 | `test-driven-development` | 先写失败测试并亲眼确认红灯 |
| 交付、完成或晋级前 | `verification-before-completion` | 运行新鲜验证，不能凭推断宣布完成 |
| 需要评估项目当前阶段和下一最小里程碑 | `quant-project-review` | 只评估，不把复盘问题直接当实现授权 |

如涉及前后端触发计算、缓存刷新或删除，额外读取 `quant-develop` 的 `references/data-lifecycle.md`。如涉及正式模型或策略信号，额外读取 `quant-develop` 的 `references/validation.md` 和 `references/output-contracts.md`。

## 增量开发流程

### 1. 锁定不可延迟的骨架

在第一轮代码前，至少明确：

- 假设、适用范围和不适用条件；
- 数据字段语义、单位、日期精度、交易日/自然日口径和 PIT；
- 样本范围、基准、费用、换手和核心评价指标；
- 输出 schema、版本、消费方和失败条件；
- 页面模式：静态研究报告、候选评审、定型跟踪或只读监控。

这些内容可以先是最小版本，但不能隐式留给后续猜测。

### 2. 定义本轮最小闭环

每轮只选择一个主要目标，例如：

- 数据读取 → 核心计算 → 结构化结果；
- 结果 → 静态回测评审页；
- 一个 API 查询 → 一个真实表格/图表状态；
- 一个计算任务 → queued/running/success/failed 状态闭环；
- 一个字段或口径变更 → 契约、适配层和回归验证。

同时写出本轮不做的功能。不要在同一轮同时重写模型、迁移存储、增加多个页面和接入工作流，除非它们是同一闭环不可分割的组成部分。

mock 数据只允许验证布局、交互和状态渲染；必须在页面和证据包中明确标注为 mock，不得用它支持策略收益、风险、口径或生产可用性结论。接入真实数据后，必须重新完成量化可信度线。

### 3. 先实现最小范围，再验证

按专业 skill 实现，并在本轮结束前独立检查两条线：

**量化可信度线**

- 数据源、字段、单位和时间方向正确；
- 日期覆盖、唯一键、缺失和异常值已检查；
- 没有未来信息、隐式最新快照或未声明 fallback；
- 结果可复跑，并能与基准、独立计算或人工样本交叉核对；
- 主结果、参数和审计证据可由同一 `run_id` 关联。

**代码/界面可靠性线**

- CLI、后端或页面核心路径真实运行过；
- API schema、空值和错误路径与前端绑定一致；
- 筛选、排序、选择、刷新或提交等本轮交互真实改变状态；
- loading、empty、error 及异步任务状态不会被伪装成成功；
- 慢响应、重复提交、页面重载和数据刷新不会覆盖新选择或留下旧状态。

一条线通过不能替代另一条线。页面能点通不代表模型口径正确，回测有数值也不代表接口和状态可靠。

### 4. 生成迭代证据包并等待确认

每轮结束必须记录目标、非目标、修改范围、输入和参数、运行命令、验证结果、截图或关键输出、未验证事项、已知风险和人工结论。可使用 [迭代证据模板](references/iteration-evidence-template.md)。

人工结论只能是：

- `继续`：本轮闭环成立，进入下一轮；
- `修正`：保留当前轮范围，先修复明确问题；
- `回退`：本轮破坏已有行为或证据不足，恢复到上一稳定点；
- `升级`：达到 candidate/production/monitor_only 或需要正式工程能力；
- `暂停/淘汰`：假设、数据、结果或投入产出比不再支持继续。

没有人工结论，不要自动扩大范围或宣称项目成熟。

## 阶段路由建议

| 阶段 | 最小交付 | 默认页面 | 退出条件 |
|---|---|---|---|
| 想法/原型 | 假设、最小样本、可运行计算 | 无或临时结果 | 结果值得继续，且口径可说明 |
| 研究 | 可复跑入口、参数、覆盖检查、静态评审产物 | 静态 HTML/preview | 关键验证通过，失败条件已知 |
| 候选 | 冻结配置、输出契约、样本外/稳健性证据 | 候选评审页 | 晋级标准满足并留痕 |
| 正式模型 | 标准快照、运行状态、日志、监控和下游消费 | 跟踪工作台 | 运行和发布门禁稳定 |
| 只读监控 | 监控快照、状态变化、告警和证据下钻 | `read_only_monitor` | 指标口径和刷新链路稳定 |

不要因为完成了 preview、页面或一次回测，就把项目标成 `production`。

## 跨层增量变更

当一轮同时修改模型、API、存储或前端时，先列出影响矩阵：

| 层 | 需要说明 |
|---|---|
| 模型/数据 | 假设、参数、PIT、样本和结果是否改变 |
| 输出契约 | 字段、类型、单位、版本和兼容策略 |
| API/任务 | 请求 allowlist、状态、幂等、并发和错误码 |
| 前端 | 绑定字段、空态/错误态、过期响应和刷新逻辑 |
| 历史资产 | 旧结果、缓存、manifest、截图和回滚方式 |

跨层变更不能以“只是显示字段”“内部接口”或“一次性 demo”为理由跳过契约和回归验证。若金融口径、回测方法或输出 schema 改变，必须提高验证级别并明确版本或迁移策略。

如果存在仍在使用的旧客户端、工作流或下游快照，先冻结旧契约并盘点消费者、版本和回滚点。默认采用新增字段、适配层、双读或版本化接口等兼容式演进；禁止仅因“同一仓库”就直接删除/改义字段。确需破坏性变更时，必须先写迁移与弃用窗口，并分别验证旧客户端、新客户端、缓存失效和回滚路径。

## AI 交互约束

每轮要求 AI 按以下顺序工作并返回：

1. 复述本轮目标、假设、非目标和影响范围；
2. 读取与本轮直接相关的项目文件和专业 skill；
3. 只实现本轮允许的范围；
4. 运行与风险相称的测试、样本检查、接口 smoke 或浏览器操作；
5. 返回修改文件、验证命令和原始结果、未验证事项、已知风险及下一步建议；
6. 等待人工结论，不把建议当授权。

不要接受“代码已完成”“页面看起来正常”“测试应该会通过”“数据已经清洗过”等没有新鲜证据的表述。

页面模式无法根据用户、主要动作和成功标准唯一判断时，按 `frontend-page-router` 的 unclear 分支先问一个问题；不得因为用户说“要交互”就默认建设工作台，也不得因为页面可筛选就跳过 report/ops 路由。

## 红线

发现以下任一情况时停止扩展，先修复或请求确认：

- 未定义数据字段、单位、时间口径或 PIT 就开始回测；
- 用最新快照、隐式前向填充或宽松 fallback 代替目标日期可见数据；
- 前端复制金融逻辑、拼接 SQL、直接读内部临时表或直接删除文件；
- 只验证 happy path，隐藏空态、失败、部分成功、重复提交或旧响应覆盖；
- 同一补丁同时改变模型口径和多个消费层，却没有影响矩阵与回归证据；
- 存在旧客户端或下游消费者，却未冻结旧契约、盘点兼容范围、安排迁移/弃用和回滚验证；
- 先写代码后补关键测试，或只凭手点/截图宣布量化结果可信；
- 用未标注的 mock、静态占位数据或最新快照支持策略结论；
- 用页面完成度、交互次数或 AI 自评代替晋级证据；
- 发现未验证的关键事项，却继续扩大本轮范围。

## 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 没有前端就跳过路由 | 模型开发本身也需要假设、PIT、输出和验证 |
| 一上来建完整平台 | 退回最小研究闭环，明确消费方和升级信号 |
| 先做 dashboard 再接模型 | 先确定页面模式和标准输出，再做真实数据 preview |
| 多轮打补丁但不留记录 | 每轮生成证据包，登记技术债和未验证事项 |
| 把测试通过当策略有效 | 增加基准、独立样本、口径和约束验证 |
| 页面能展示就算联调完成 | 真实检查 loading、empty、error、过期响应和刷新后状态 |

## 交付前自检

- [ ] 已确认这是新量化对象开发，而非轻量研究或孤立小修复
- [ ] 已定义当前阶段、最小闭环和非目标
- [ ] 已路由到正确的量化、前端、调试和验证 skill
- [ ] 已检查数据语义、PIT、覆盖、基准、费用和输出契约
- [ ] 已分别完成量化可信度线和代码/界面可靠性线
- [ ] 已保存本轮证据包并由人工选择继续、修正、回退、升级或暂停
- [ ] 未把 preview、页面完成度或一次成功运行误判为项目成熟

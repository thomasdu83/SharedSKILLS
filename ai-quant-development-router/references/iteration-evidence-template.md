# AI 量化开发迭代证据包

每轮只记录能支持下一步判断的事实；不要把聊天全文当作证据。

```markdown
# <项目/策略> 迭代 <编号>：<本轮目标>

## 本轮边界

- 目标：
- 非目标：
- 当前阶段：idea / research / candidate / production / monitor_only
- 人工决策：继续 / 修正 / 回退 / 升级 / 暂停淘汰

## 量化口径

- 假设与适用范围：
- 数据源与版本：
- 关键字段、单位和时间语义：
- 目标区间与 PIT/as_of 规则：
- 基准、费用、换手和评价指标：
- 输出契约/版本：

## 变更影响

- 修改文件：
- 模型/数据影响：无 / 有，说明：
- API/任务影响：无 / 有，说明：
- 前端影响：无 / 有，说明：
- 历史结果、缓存或兼容性影响：

## 验证证据

- 运行命令：
- 退出码：
- 测试/接口 smoke 结果：
- 输入行数、日期范围、缺失、重复和覆盖：
- 关键结果或基准对照：
- 页面操作路径、截图或关键状态：
- run_id / manifest / 输出路径：

## 未验证事项与风险

- 未验证：
- 已知限制：
- 临时兼容逻辑或技术债：
- 下一轮要证伪的假设：

## 人工结论依据

说明为什么选择继续、修正、回退、升级或暂停；不要只写“看起来正常”。
```

## 最小证据要求

- 研究计算轮：运行入口 + 样本/口径检查 + 结构化输出。
- 报告或 preview 轮：真实结果 + 静态渲染/截图 + 结论和 caveat 可读。
- API/前端联调轮：真实请求 + loading/empty/error 或任务状态 + 刷新后状态。
- 跨层变更轮：影响矩阵 + 契约/兼容检查 + 最小端到端验证。
- 晋级轮：阶段标准、失败条件、历史证据和人工决议完整。

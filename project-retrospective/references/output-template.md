# Project Retrospective Template

Use this template to produce a compact postmortem and decide what should be kept as reusable knowledge.

## Output template

### 1. 项目结论
- 一句话结论
- 是否达成目标
- 最值得记住的结果

### 2. 目标与结果
- 原始目标
- 实际交付
- 偏差点

### 3. 成功经验
- 哪些做法有效
- 哪些设计可以复用
- 哪些是跨项目稳定模式

### 4. 失败 / 风险
- 主要问题
- 触发原因
- 可避免的红线

### 5. 可复用规则
- 只写会改变未来行为的规则
- 写成可执行的检查项
- 优先抽象成“以后遇到同类场景就怎么做”

### 6. 不建议沉淀为 skill 的细节
- 项目特有数字
- 单次环境约束
- 一次性权衡
- 只对当前项目成立的命名或路径

### 7. 下次同类项目检查清单
- 先确认目标是否稳定
- 先找重复出现的模式
- 先分清事实和推断
- 先判断是否值得升级为 skill

### 8. 回写到共享 skill
- 目标 skill：`F:\Thomas\SharedSKILLS\...`
- 变更类型：新增 / 修改 / 删除
- 建议写入的具体条目：
- 是否足够稳定，值得沉淀：是 / 否 / 待确认
- 备注：

## Promote-to-skill rule

Create or update a reusable skill only when the pattern is:
- repeated across projects,
- stable enough to guide future behavior, and
- not tied to one data source, one UI, or one-off deadline pressure.
